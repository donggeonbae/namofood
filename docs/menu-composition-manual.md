# 나모푸드 식단 작성 매뉴얼

기준일: 2026-10-08 · 적용 대상: 조식·중식·석식·야식 수동 작성

운영 변경: AI 식단 자동 편성은 종료했다. 현재 AI 작성 식단은 백업 후 삭제하고, 이후 식단은 아래 분류로 직접 선택한다. 레시피 자동 작성은 별도로 유지한다. 2026-10-09 추가된 AI 주간 추천 목록은 후보를 미리 준비해 서버에 별도로 보관하는 기능이며, 사용자가 선택한 한 칸만 수동 식단으로 반영한다.

## 1. 운영 방향

한 끼 10,000원. 일반 함바보다 높은 가격을 **확실한 주찬의 품질과 ‘메인이 하나 더 있는’ 구성**으로 설명할 수 있어야 한다. 공장 근무자가 식판을 받았을 때 먹을 것이 많고 든든하다고 느끼는 급식이다. 가짓수만 늘린 나물·샐러드 위주의 가정식, 같은 재료 이름만 바꾼 메뉴 나열을 피한다.

이 기준은 AI 초안 자체를 좋은 식단의 근거로 삼지 않는다. 현재 저장 자료와 9/28·10/1·10/4·10/7 저장본을 비교해 **사람이 바꾼 것으로 확인된 22끼** 중 명확한 구성 사례를 참고했다. 과거 식단의 오타·임시 입력·칸 배치 오류까지 정답으로 복제하지 않는다.

## 2. 한 끼의 기본 구성

- 쌀밥은 기본 제공. 별도 반찬 수나 추가 주찬으로 세지 않는다.
- 편집 기본 칸은 **국·메인1(고기)·메인2(생선/해산물)·메인3(기타 주찬)·부찬1(야채)·부찬2(야채)**의 6칸이다. 쌀밥은 별도 기본 제공하며 추가 메뉴를 자유롭게 더하고 뺀다.
- 고기는 소·돼지·닭·오리를 한 상위 분류로 묶는다. 종류별 소분류는 기본으로 접어 놓고 필요할 때 펼친다. 메뉴를 찾는 순서는 **주재료 → 조리방식**이다.
- 고기 조리방식은 볶음·구이·찜·조림·튀김·부침·삶음으로 선택한다. 수육·보쌈은 삶음으로 찾으며, 세부 고기 종류와 조리방식을 함께 좁힐 수 있다. 분류를 바꿔도 저장된 식단·레시피 내용은 자동 수정하지 않는다.
- 메인 세 개는 각각 따로 배식할 수 있는 실속 있는 주찬이다. 기타 주찬은 고기·생선/해산물·야채를 제외한 계란·두부·떡 등의 요리다. 튀김·전은 조리방식이며 실제 주재료에 따라 분류한다. 감자튀김이나 야채전은 야채, 계란말이·두부부침은 기타 주찬으로 찾는다.
- 김치 1종과 서로 다른 곁들임을 갖춘다. 샐러드·쌈·장아찌는 주찬에 맞게 붙인다. 김치·국·감자튀김·나물·과일·음료·후식은 ‘메인 하나 더’로 계산하지 않는다.
- 국은 실제 국·탕·찌개다. 국수·우동·라면을 국 칸에 넣지 않는다. 국물에 고기가 들어간다고 별도 주찬을 빼지 않는다.

**기본형:** 쌀밥 + 국 + 고기 주찬 + 생선/해산물 주찬 + 기타 주찬 + 야채 부찬 2종. 김치는 야채 부찬 또는 추가 메뉴에서 선택한다.

기존 저장 식단의 칸 값은 화면 분류가 바뀌었다고 자동 이동하거나 바꾸지 않는다. 사람의 선택 없이 메뉴·식수·근무 자료를 덮어쓰지 않는다.

## 3. 실제 수정 식단에서 가져온 구성 원칙

| 확인 사례 | 주찬 구성의 참고점 |
| --- | --- |
| 10/5 석식: 고등어구이·위샹로우스·닭강정 | 생선 + 고기볶음 + 인기 있는 닭요리로 체감 주찬을 세 종류 확보. 닭강정은 부찬 칸에 있어도 주찬급 보강으로 본다. |
| 10/6 석식: 대패삼겹콩나물볶음·동그랑땡·왕교자튀김 | 확실한 고기 주찬에 전/완자·만두를 더해 식판이 풍성해지는 구성. |
| 9/30 중식: 고추장삼겹·만두튀김 초고추장무침·탕수육·새우튀김 | 고기·튀김·해물을 보강하는 방향을 참고한다. 튀김을 한 끼에 모두 복제하지 않고 작업량과 식감을 나눈다. |
| 10/8 중식: 훈제오리무쌈·깐풍새우, 부추무침·겉절이 | 주찬 재료와 조리법을 다르게 하고, 무쌈·부추·겉절이를 해당 주찬에 맞춰 붙인다. 현재 수동 작성에서는 기타 주찬을 더해 세 메인을 구성한다. |

사례는 긍정적인 조합을 추출하기 위한 자료다. 해당 식단 전체가 현재 칸 구성을 모두 충족했다는 뜻은 아니다.

## 4. 퀄리티와 조합

- 익숙하고 실제 급식에서 설명 가능한 이름을 쓴다. 제육·수육·불고기·닭갈비·찜닭·닭강정·돈가스·탕수육·생선구이/조림·오징어볶음 등의 주찬군을 바탕으로 조리법과 양념을 바꾼다.
- 서로 다른 단백질과 조리법을 조합한다. 예: 고기볶음 + 생선구이 + 계란말이, 수육 + 매콤한 해물요리 + 두부부침. 같은 양념 볶음 셋 또는 튀김 셋으로 채우지 않는다.
- 달걀·두부·소시지·만두는 좋은 보강 수단이지만, 값싼 보강 메뉴만 늘려 메인 재료를 줄이는 방식으로 쓰지 않는다. 고기 몇 조각이 들어간 채소볶음도 고기 주찬으로 과대 계산하지 않는다.
- 이름에 ‘수제·특선·프리미엄’만 붙여 품질을 주장하지 않는다. 실제 주재료 양, 크기·손질 상태, 식감, 소스 별도 제공, 배식 직전 마무리로 품질을 만든다.
- 계절에 맞는 곁들임을 사용한다. 낯선 채소 조합을 무작위로 늘려 다양성을 채우지 않는다.
- 꽃게·장어·고가 스테이크 등 비싼 재료만 연속 편성하지 않는다. 구체적인 원가는 발주 단가·손질 수율·식수에 따라 현장에서 확인한다. 이 매뉴얼이 원가나 실제 제공량을 보증하지는 않는다.
- 영양 균형은 최우선 편성 기준이 아니지만 식품 안전은 생략하지 않는다. 술·주류형 음료는 모든 칸에서 제외한다.

## 5. 주간 다양성과 대량 조리

- 앞뒤 7일의 끼니와 추가 메뉴를 확인해 같은 주찬/별칭이 자주 반복되지 않게 작성한다.
- 제육볶음/돈육고추장볶음, 돈가스/돈까스처럼 실제로 같은 음식은 하나로 본다. 간장불고기와 고추장불고기처럼 실제 조리가 다른 메뉴는 구별한다.
- 한 끼 안에서 단백질·조리법·양념 조합이 겹치지 않게 하고, 하루 4식의 국과 곁들임도 다양하게 배치한다. 현재 화면이 주간 중복을 자동 차단하는 것은 아니다.
- 100~500인분을 회전솥·대형 볶음솥·스팀/컨벡션 오븐·튀김기·배식 밧드로 만들 수 있는 메뉴를 선택한다. 가정용 프라이팬을 한 접시씩 돌리는 작업서는 쓰지 않는다.
- 같은 원재료의 전처리를 공유하되 메뉴를 복제하지 않는다. 주찬 세 개를 모두 즉석 튀김으로 짜서 배식 시간에 작업이 몰리지 않게 한다.
- 조리법과 재료가 완성된 등록 레시피를 우선 쓴다. 이름이 불명확하거나 확인 요청 중인 메뉴는 조리 담당자가 먼저 확인한다.

## 6. 수동 작성·적용 전 확인

1. 국 1개, 고기·생선/해산물·기타 주찬의 메인 3개, 야채 부찬 2개가 있는가?
2. 세 메인이 각각 실속 있는 메뉴인가? 국·나물·후식만으로 주찬을 대체한 것은 아닌가?
3. 고기/생선/해물 중심 메뉴가 있으며, 조합과 대량 조리 동선이 현실적인가?
4. 앞뒤 한 주의 실제 음식·별칭·조리 조합과 겹치지 않는가?
5. 새 메뉴의 레시피가 준비됐는가? 식수·직접 입력·가격·직원 자료는 유지되는가?

식단 자동 생성과 자동 재시도는 중지됐다. 자동 편성 배너·식단의 AI 작성 표시는 제거한다. 운영자의 명시적인 요청에 따라 현재 AI 표시된 식단 내용은 날짜와 관계없이 백업 후 정리하되, 직접 수정해 AI 표시가 풀린 식단·식수·쌀밥·레시피는 그대로 유지한다. 새 식단은 직접 고르고 적용한 끼니만 저장한다.

## 7. AI 주간 추천 목록 사용 기준

- 국·고기·생선/해산물·기타 주찬·야채 부찬 두 자리에 각각 3개씩 추천한다. 쌀밥은 추천 대상이 아니라 기본 제공이다. 네 끼니가 해당 날짜의 후보 목록을 공유하며 실제 구성은 운영자가 선택한다.
- 이름·재료·양수 분량·조리법이 준비되고 확인 보류 중이 아닌 등록 레시피만 사용한다. 무작위로 후보군을 추린 뒤 모델이 위 매뉴얼의 맛·양·대량 조리 작업성과 조리법 다양성을 고려한다.
- 앞뒤 7일과 당일의 실제 음식·추가 메뉴를 확인하고 같은 메뉴/별칭을 후보에서 제외한다. 충분한 후보가 없으면 숫자를 채우기 위해 미등록 음식이나 중복을 만들지 않고 부족함을 안내한다.
- 조회만으로 식단·식수·근무 자료를 변경하지 않는다. 후보를 눌렀을 때만 지정한 날짜·끼니의 한 칸에 반영하고, 기존 음식이 있으면 교체 확인을 받는다. 임시 식단은 기존 적용 절차를 따른다.
- 매일 오전 6시 5분(KST)에 오늘부터 2주 뒤까지의 추천을 확인하고 누락·실패한 날짜는 5분마다 보충한다. 완성된 추천은 유지한다. 화면에서는 선택한 월요일~일요일의 후보를 불러오고, 각 칸의 ‘＋ 고르기 → AI 추천 펼치기’에서 해당 자리의 추천 3개를 보여준다. 주간 현황과 선택창의 추천은 기본으로 접어 둔다.
- 같은 날짜의 원본 후보는 실제 식단과 분리한 서버 테이블에 보관해 다른 기기에서도 공유한다. 옛 브라우저 추천 저장은 사용하지 않는다. 레시피가 바뀌면 요청 시 갱신하지만 식단 선택만으로 다시 생성하지 않는다. 선택창을 열 때마다 현재 앞뒤 식단과 별칭을 다시 확인하며, 이미 선택된 후보가 빠지면 남은 수와 부족함을 그대로 알린다.
- 모든 기기·서버 일정의 생성을 원자적 작업 임대로 최대 2개씩 제한하고, 보고 있지 않은 이전 주의 브라우저 대기 요청은 취소한다. 생성 중인 날짜는 제한된 시간 동안 기다린다. 화면의 실패는 재시도 버튼으로, 서버의 누락 보충은 별도 일정으로 처리한다. AI 실행 없이 무작위로 뽑은 메뉴를 AI 추천으로 가장하지 않는다.
- 주간 준비 현황과 선택창의 AI 출처·모델은 작성 화면에서만 보여준다. 외부 공지·인쇄에는 넣지 않는다. 식단 자동 편성 cron과 기존 중지 요청 처리는 그대로 유지한다.
